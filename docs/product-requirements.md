# 产品需求

## 1. 产品定位

AI 服装设计与改款助手以一张真实服装图为起点，结合用户明确的保留项、修改目标和风格方向，产出设计思路与服装效果图。

产品价值不是提供固定部件替换，而是帮助用户在面料、廓形、结构、部件、工艺、辅料、色彩和搭配关系上形成完整的新款方向。

## 2. 目标用户

### 2.1 服装设计师

核心需求：

- 从已有款式快速扩展灵感。
- 观察不同结构、工艺和风格组合。
- 在进入草图、打版前低成本筛选方向。

### 2.2 服装档口与小型商家

核心需求：

- 基于畅销款快速衍生新款。
- 保留供应链已经具备的面料或关键元素。
- 快速得到便于选款、沟通和打样的视觉方案。

## 3. 首版模式

### 3.1 灵感设计

- 允许较大的风格和结构变化。
- 系统先提出多个文字方向。
- 用户选中一个方向后生成图片。
- 强调差异度、创意性和设计说明。

### 3.2 快速衍生

- 优先保留原款识别度和供应链可行性。
- 用户必须明确保留项。
- 改款建议强调结构合理、工艺可实现和成本可控。
- 默认生成一个较稳妥的方案，可追加方案。

## 4. 核心用户流程

1. 用户进入 H5，选择灵感设计或快速衍生。
2. 上传一张服装原图。
3. 填写或勾选：
   - 必须保留的元素。
   - 希望改变的部分。
   - 目标风格、季节、品类和人群。
   - 改款幅度。
4. 系统分析原款并形成设计方向。
5. 用户选择或修改其中一个方向。
6. 系统提交生图任务并展示进度。
7. 用户查看结果，选择继续修改、重新生成、保存或下载。

## 5. 首版功能需求

### 5.1 图片输入

- 支持 JPG、PNG 和 WEBP。
- 在上传前检查文件类型、尺寸和大小。
- 展示上传进度、失败原因和重新上传入口。
- 不在客户端长期保存完整 Base64。

### 5.2 改款需求输入

- 保留项支持自由输入和常用选项。
- 修改目标覆盖但不限于：廓形、衣长、领型、门襟、袖型、口袋、分割线、拼接、面料、颜色、工艺和辅料。
- 用户可以指定低、中、高三档改款幅度。
- 用户可以补充自然语言要求。

### 5.3 设计方向

- 每个方向包含名称、风格说明、关键结构变化、保留项和适用场景。
- 快速衍生模式必须说明生产可行性风险。
- 方向文字生成失败时，不得自动消耗生图次数。

### 5.4 图片生成

- 默认一次生成一张。
- 明确展示生成中、成功、失败和可重试状态。
- 同一个任务保留所用模型、模型版本、提示词版本和参数。
- 重试必须防止重复扣费和重复提交。

### 5.5 结果与迭代

- 展示原图、结果图和改款摘要。
- 支持输入一条追加修改指令。
- 支持下载结果图。
- 匿名用户可以在当前设备查看近期任务。

## 6. 首版非目标

- 不输出可直接生产的纸样。
- 不承诺尺寸与版型数据准确。
- 不生成完整 BOM、尺寸表和工艺单。
- 不提供虚拟试衣或模特换装。
- 不做3D服装仿真。
- 不做在线支付、套餐或复杂会员体系。
- 不做社区、作品公开发布或社交互动。

## 7. 数据与隐私

- 匿名任务默认保留7天，最终期限在部署前结合存储成本和隐私要求确认。
- 用户必须能够删除自己的任务和图片。
- 原图与结果图使用不可预测的对象键，不公开目录列表。
- 正式上线前提供隐私政策、用户协议和 AI 生成内容说明。

## 8. MVP 验收标准

- 手机浏览器可以完成上传、填写要求、提交和查看结果的完整流程。
- 服务端能够调用至少一个国产模型并保存结果。
- “保留格纹袖口、改成复古工装款”基准任务可完成。
- API Key 不出现在客户端包、网络响应、日志和 Git 历史中。
- 每个任务的模型、提示词版本、状态、耗时和结果可追踪。
- 关键失败场景有用户可理解的提示并可安全重试。
