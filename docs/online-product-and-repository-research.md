## 1. 阅读和使用规则

本文档帮助新开发窗口理解“为什么优化、参考了什么、可以如何实施”。使用时必须遵守：

1. 先阅读 `AGENTS.md`、`README.md` 和 [当前状态](current-status.md)。
2. 本文列出的外部产品能力主要来自官网公开说明，除非明确标注，否则尚未用付费账号完成同图实测。
3. GitHub 仓库用于借鉴产品方法、评测方法或工程结构，不表示可以直接复制代码、权重或数据。
4. 开始实现候选项前，必须核对当前里程碑、许可证、模型服务条款、成本和跨端约束。
5. 候选项只有在产品需求、验收条件和当前状态同步更新后，才能成为正式开发任务。

## 2. 产品定位和当前基线

本项目服务两个核心场景：

- **灵感设计**：帮助服装设计师从已有款式探索多个有差异的设计方向。
- **快速衍生**：帮助服装档口保留畅销款或供应链关键元素，快速得到相对稳妥的新款方向。

产品不是固定的领型、口袋替换器。改款维度可包括廓形、比例、结构分割、部件、面料、拼接、色彩、洗水、工艺、辅料、功能和风格语义。

截至2026-08-27，和本轮优化直接相关的当前基线是：

- 已有两种业务模式，以及保留项、修改要求、风格和低/中/高改款幅度输入。
- 已有 `garment-dna-v0.2` 原款分析、可见事实证据门和三个结构化设计方向。
- 用户选择方向后默认生成一张；支持同方向再生成、继续修改、本次会话历史和下载。
- 继续修改每次从原始商品图、选中方向和累计指令重建，不编辑上一张模型生成图。
- 生图已经使用可轮询异步任务；分析仍是同步请求。
- 当前里程碑是微信小程序体验版的云函数、持久任务、存储、OpenID 和真机链路，不是本文全部优化项。

完整且唯一准确的实施状态仍以 [当前状态](current-status.md) 为准。

### 3.1 产品调研的共同结论

外部产品中反复出现且适合本项目的交互模式是：

- 用结构化选项降低自由提示词门槛。
- 明确区分必须保留的元素和允许改变的维度。
- 用参考强度控制与原款的距离。
- 先选择方向，再按颜色、材质、结构或局部继续衍生。
- 生成结果不是流程终点，而是后续动作的输入。
- 品牌历史和私有资料适合长期个性化，但不应阻塞首版验证。

### 4.4 对 GitHub 调研的统一结论

最值得采用的不是某个旧模型权重，而是以下方法：

1. 视觉模型只提取结构化可见事实，业务规则决定哪些事实可以进入提示词。
2. 把改款动作做成稳定分类，支持单一维度和组合维度测试。
3. 生图后比较原图、指令和结果，分别评价保留度、遵循度、真实性和结构合理性。
4. 自动评分只负责筛选或提示风险，不能代替设计师和档口最终确认。
5. 对每次测试保存模型、提示词版本、参数、耗时、费用和人工评分。
6. 外部仓库没有一个可以完整替代本项目现有 Taro、Provider、证据门和国产模型链路。

## 5. 候选产品优化清单

以下编号用于后续 Issue、提交和文档引用。除非 [当前状态](current-status.md) 明确标为已实现，否则全部视为候选能力。

### 5.1 P0：小程序体验链路稳定后的首批优化

#### OPT-001：分析结果转成可锁定保留项

实施进度：已完成代码与自动化，待真实模型/真机交互验收。当前只把证据门采纳的高置信度可见事实作为候选，用户明确确认后才进入 Prompt Compiler；不会默认锁定全部分析事实。

- 从高置信度 `visible` 事实中生成可选标签，例如格纹袖口、牛仔面料和短款比例。
- 标签只提供建议，用户可取消、修改或增加自由文本。
- 锁定项必须进入确定性 Prompt Compiler，并在结果核对中逐项检查。
- 不得把 `inferred`、`unknown` 或低置信度事实默认锁定。

#### OPT-002：结构化改款维度

- 至少覆盖廓形与松量、长短比例、结构分割、部件、面料拼接、色彩洗水、工艺辅料、功能和风格场景。
- 支持只改变一个维度，也支持少量组合；自由文本继续作为补充。
- 领域协议而不是页面组件保存正式枚举和兼容规则。

#### OPT-003：解释改款幅度

实施进度：已完成三档移动端产品语义说明，待体验成员验证是否易懂；没有使用虚假精确百分比。

- 轻度：主体版型不变，主要修改细节。
- 中度：保留识别特征，允许调整结构和比例。
- 重度：只强制保留锁定元素，允许整体重构。
- 这是产品语义和提示词策略，不承诺模型能达到精确百分比。

#### OPT-004：增强设计方向卡片

实施进度：已完成移动端渐进展开版本，待真实分析结果真机验收。未选中卡片展示摘要、变化维度和风险，选中后展开继承保留项、幅度、具体改款与理由。

每个方向应明确展示：

- 设计主题和适用场景。
- 继承的锁定项。
- 主要变化维度和具体改款清单。
- 与原款距离或改款幅度。
- 生产风险和需要人工确认的推断。

用户仍需选择方向后才触发一次付费生图。

#### OPT-005：结果页单维度继续衍生

实施进度：首个纵向切片已完成本地代码、自动化和 H5 无费用链路验证。结果页提供三个单维度入口和两个幅度入口，一次只能选择一个；允许不填文字直接生成，也允许叠加自由文字和常见问题。所有输入由共享领域规则确定性编译，并在现有版本指令中留痕；仍从最初商品图重建，不把生成图作为像素输入。真机首次验证发现 Qwen Image 在同一浅灰蓝外套上连续三次未落实换色，即使最后明确要求红色也仍保留旧主色。针对该失败，色彩入口增加明确目标色选项，模糊“颜色不好看”不再直接消耗额度；确定性 Prompt 把目标色提升为主体大面积换色硬约束，并规定同维度最新替换值覆盖原图事实、基础方向和旧修改。修复已通过自动化和327/390px无费用界面检查，仍待部署后真实复测，因此 OPT-005 暂不标记为整体完成。

首批快捷动作建议为：

- 按同一方向再出一款。
- 只调整廓形或比例。
- 只调整面料或拼接。
- 只调整颜色、洗水或工艺。
- 降低或提高改款幅度。

快捷动作必须转换成可追踪的结构化请求，继续沿用原图重建策略，不能把模型生成图作为下一轮像素输入。

#### OPT-006：生成结果核对报告

实施进度：已完成不额外计费的人工结构化核对计划。普通用户默认只选“满意/需要修改”，需要修改时可直接输入自然语言，也可勾选常见问题；两者由确定性规则合并，只有明确点击生成下一版才占用生图额度。逐项状态降为可选专业入口。状态仅保留在本次页面；自动视觉核对、证据说明和持久评测记录仍未实现，因此 OPT-006 尚未整体完成。

核对至少区分：

- 锁定项是否保留。
- 指定变化是否落实。
- 是否出现未要求的明显变化。
- 是否存在文字、水印、服装结构和图像质量异常。

结果使用“通过、存疑、未通过”及证据说明。自动核对不得宣称生产可用，也不得自动隐藏失败图而不保留可追踪记录。

### 5.2 P1：形成连续设计工作流

#### OPT-007：局部改款

- 第一阶段使用模型分析得到的领口、袖口、口袋、门襟和下摆等区域选择。
- 第二阶段再评估移动端手指圈选和蒙版上传。
- 需要先定义跨 H5/微信兼容的区域或蒙版协议，禁止页面直接依赖 Canvas/DOM 实现业务契约。

#### OPT-008：改款玩法模板

候选模板包括复古工装、通勤极简、户外机能、街头年轻、畅销款轻改、面辅料降本和季节转换。模板必须展开成可查看、可修改的结构化要求，不能隐藏成不可解释的提示词。

#### OPT-009：系列化衍生

- 同版不同色。
- 同风格不同结构。
- 同核心元素不同品类。
- 基础款、主推款和形象款组合。

默认仍一次生成一张。批量任务只有在预算、并发、取消和持久幂等完成后才能开放。

#### OPT-010：项目和系列画板

结果可以按档口/品牌、季节、系列和主题归档，并保留原图、方向、版本关系、模型和提示词版本。它依赖当前设备近期任务和持久项目数据先完成。

#### OPT-011：款式图辅助输出

允许把已选效果图转成正面平铺参考图或简化款式图，但必须标注为视觉参考，不是纸样、尺寸表或完整工艺单。

### 5.3 P2：长期个性化和产品壁垒

#### OPT-012：品牌/档口偏好记忆

记录经过用户确认的常用版型、价格带、目标人群、风格、面辅料和禁用元素。默认不能把模型推断当作品牌事实，且必须支持查看、修改和删除。

#### OPT-013：私有灵感资料库

允许用户保存自有爆款、旧款、面料和灵感图，并只在自己的权限范围内检索。需要先完成身份、对象存储、删除、过期和数据隔离。

#### OPT-014：趋势和商品资料辅助

接入有授权的趋势、色彩、面料或商品数据，为设计方向提供可追踪来源。未经授权的图片抓取和来源不明的训练数据不能进入产品。

#### OPT-015：多模型候选和自动选图

按固定样本比较原款保留度、指令遵循、结构合理性、真实性、差异度、耗时和成本。多模型自动路由必须晚于单模型链路稳定，不得在缺少真实评测时增加复杂度。

## 6. 推荐实施顺序

本文调研不改变当前小程序体验版里程碑。推荐顺序是：

1. 完成云存储、云函数、持久任务/幂等/额度、OpenID 权限和假 Provider 验收。
2. 在明确预算内完成一次真机真实模型链路，确认云函数时限和结果转存。
3. 从 OPT-001 至 OPT-006 中按独立纵向切片实施，优先锁定保留项和结果核对。
4. 用固定样本和少量体验成员反馈决定是否推进局部改款、模板和系列化衍生。
5. 在身份、项目和数据删除机制稳定后，再考虑品牌记忆和私有资料库。

当前不能把 P0/P1/P2 理解成已经承诺的发布日期，也不能跳过当前里程碑直接扩大公开试用范围。

## 7. 线上产品同图测试方法

后续需要对产品和模型进行同图实测时，统一使用相同原图和相同需求，避免只比较官网精选案例。基础任务继续使用：

> 改成复古工装款，保留格纹袖口。

每个产品至少记录：

| 维度 | 记录内容                                               |
| ---- | ------------------------------------------------------ |
| 输入 | 是否支持原款图、保留项、结构化维度、局部区域和参考强度 |
| 流程 | 是否先给方向、是否默认多图、是否支持从结果继续编辑     |
| 保留 | 格纹袖口、主面料、主体比例和原款识别特征的保留情况     |
| 改款 | 工装结构、比例、口袋、分割、工艺和材质变化是否落实     |
| 异常 | 文字/水印复现、正反面翻转、结构错误、噪点和风格漂移    |
| 效率 | 分析耗时、生图耗时、失败率、每次积分或人民币成本       |
| 输出 | 分辨率、下载、历史、继续编辑、款式图或系列组织能力     |
| 权利 | 试用限制、商业使用、用户素材、生成内容和隐私条款       |

真实测试结果必须追加到 [模型评测记录](model-evaluation-log.md) 或单独的产品实测记录；只阅读官网不能写成“效果已经验证”。

## 8. 明确不纳入当前首版

- 可直接生产的纸样和精确尺寸。
- 完整 BOM、尺寸表和工艺单。
- 3D 服装仿真和复杂虚拟试衣。
- 自动公开发布、社区或电商平台运营。
- 没有人工确认的生产可行性结论。
- 未完成预算和幂等保护时的一次自动批量生图。

如果这些边界需要改变，应先更新产品需求，并对难以逆转的架构或数据决定新增 ADR。
