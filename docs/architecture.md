# 系统架构

本文档同时描述当前本地实现与目标架构。第3、6、7节以当前代码为主；第4、5节包含当前边界和后续职责；第8至11节主要描述目标状态。功能是否已经交付以 [当前状态](current-status.md) 为准。

## 1. 架构目标

- H5 优先交付，同时降低后续微信小程序迁移成本。
- 模型供应商可替换，业务流程不依赖单一厂商。
- API Key 和用户图片只在受控服务端处理。
- 生图任务可追踪、可重试、可限额和可审计。

## 2. 总体结构

```text
Taro 客户端
├── H5 平台适配
└── 微信小程序平台适配
        │
        ▼
业务 API / 任务服务
├── 上传校验与资源存储
├── 证据门控与设计方向
├── 确定性 Prompt Compiler
├── 生图任务与幂等控制
└── 结果访问
        │
        ▼
Model Provider 层
├── Alibaba Qwen VL Analysis Provider
├── Alibaba Wan Provider
├── Alibaba Qwen Image Provider
└── Volcengine Seedream Provider
```

## 3. 当前仓库结构

当前正式应用采用以下结构：

```text
apps/
├── client/                 # Taro H5/微信小程序
├── server/                 # Node.js TypeScript API
└── wechat-cloud/           # 微信云函数 TypeScript 源码与部署构建
packages/
├── application/            # 跨 Fastify/云函数的用例、仓储端口与内存 Fake
├── domain/                 # 业务类型、规则和用例
└── model-providers/        # Qwen、Qwen Image、万相等模型适配器
docs/
prompts/
scripts/
```

客户端内部的 `platform/` 隔离 Taro 图片选择、结果保存、未完成任务 jobId 和微信云环境初始化能力，`services/` 通过 `GarmentGateway` 隔离业务页面与传输实现。当前 H5 使用 HTTP 网关；微信云网关已经能读取云端能力、上传原图、发起分析/生成/继续修改、轮询任务并在重进页面后恢复，另有内部诊断页验证 OpenID、云存储、云函数、数据库恢复和清理。微信业务动作只在云函数显式启用 `fake` 或配置完整的 `alibaba-qwen` 时开放；真实环境现已通过服务端私密配置启用 `alibaba-qwen` 并完成付费真机核心链路验收。体验权限默认查询 `trial_members` 指纹白名单，受邀体验期间可以显式启用带截止时间的 `wechat-experience` 直通模式；截止时间到达或配置无效时自动回退白名单。仓库继续保留 Fake/HTTP/指纹白名单安全默认值。`apps/wechat-cloud` 保存可测试的云函数源码，构建后输出到被 Git 忽略的 `apps/client/cloudfunctions/`。共享 TypeScript、ESLint、Prettier 和 Vitest 配置当前保存在仓库根目录，达到多个实现后再提取独立配置包。

验证脚本保留在 `scripts/`，用于显式执行付费模型冒烟测试，不进入普通 CI。

## 4. 客户端边界

当前客户端已实现：

- 图片选择、压缩前预检和预览。
- 表单输入与校验。
- 同步分析，以及异步生图任务的加载、失败和结果状态。
- 创建生图任务后自动轮询，短暂查询网络错误不会创建新的付费任务。
- 服务端启用受控试用时显示访问码输入，并通过 Taro 平台存储保存在当前设备。
- 三个设计方向、生产风险和选中状态展示。
- 将证据门采纳的可见事实转换为候选保留项；用户确认后的锁定项通过同一 `GarmentGateway` 请求进入 H5 与微信云 Prompt Compiler。原始用户硬约束在当前分析内保持稳定，新增候选可在首次生图前调整。
- 方向卡使用渐进展开：未选中时显示摘要、变化维度和风险，选中后显示继承保留项、幅度说明、完整改款与理由。
- 原图/上一版与当前结果对比、本次页面会话历史、同方向再生成和继续修改。
- 根据当前锁定项、选中方向和异常类型生成本次页面内的人工核对计划；普通用户只做“满意/需要修改”快速反馈，需要修改时可输入自然语言或选择问题，客户端将两者确定性编译为继续修改指令，不额外调用解释模型。详细逐项状态作为可选入口；状态尚未持久化，也尚未调用独立视觉核对 Provider。
- 通过 Taro 平台适配层下载结果图。

目标客户端还应负责：

- 跨页面或跨重启的任务恢复与取消。
- 当前设备的匿名会话标识和近期任务。
- 平台分享入口。

客户端不得：

- 持有模型 API Key。
- 直接调用模型厂商接口。
- 将完整图片 Base64 写入本地日志或持久缓存。
- 在共享业务代码中直接调用浏览器或微信专属 API。

目标平台能力使用统一适配接口。当前已实现图片选择和结果保存适配；分享和会话接口尚未实现。完整接口草案例如：

```ts
interface PlatformAdapter {
  pickImage(): Promise<SelectedImage>;
  saveImage(url: string): Promise<void>;
  shareResult(input: ShareInput): Promise<void>;
  getSessionIdentity(): Promise<SessionIdentity>;
}
```

## 5. 服务端边界

当前服务端已实现：

- 接收受控上传并校验文件内容类型和大小。
- 构造版本化提示词。
- 调用分析和生图 Model Provider。
- 控制超时和进程内任务级幂等，不自动重复付费调用。
- 创建可查询的生图任务，并保存 `queued`、`generating`、`succeeded`、`failed` 状态。
- 可选校验共享试用访问码，并用进程内策略限制每日分析/生图额度、模型并发和生图启动间隔。
- 下载厂商临时结果并转存本地 `var/assets/`。
- 可选按保留时长清理本地 UUID 结果目录，默认关闭删除。
- 保存进程内父子生成关系，并支持从校验后的原图与累计指令重建继续修改结果。
- 返回稳定的业务错误码。

目标服务端还应负责：

- 保存可恢复、可查询、可删除和可过期的任务状态。
- 图片内容安全检查。
- 并发、用户/IP限流、额度、预算和告警。
- 将原图与结果图转存正式对象存储。

## 6. Model Provider 接口

业务层只依赖统一接口：

```ts
interface GarmentImageProvider {
  readonly provider: "alibaba-wan" | "alibaba-qwen-image" | "volcengine-seedream";
  readonly model: string;
  readonly configured: boolean;

  generateVariation(input: GarmentImageProviderInput): Promise<GarmentGenerationResult>;
}
```

生图 Provider 的统一输入包括：

- 原图受控文件引用。
- 领域层已编译的最终提示词。
- 输出数量。
- 提示词版本。

统一输出至少包括：

- Provider 和模型版本。
- 厂商请求 ID。
- 结果文件信息。
- 耗时和可获取的用量信息。
- 标准化错误。

视觉分析使用独立的 `GarmentAnalysisProvider`。它接收原图与用户简报，返回经过 Zod 校验的 `garment-dna-v0.2`；生图 Provider 不负责解释或重新组合这个结构。

## 7. 当前本地实现

微信云端的第一条真实验收切片是无模型费用的基础设施探针：白名单按 OpenID 派生的不可逆用户指纹查询，临时图片按用户指纹隔离上传，`garment-api` 将探针记录持久化并允许所属用户重新读取和主动清理。该切片已在真实独立云环境完成上传、跨请求恢复和云文件/数据库记录双重删除验收。其后新增受环境开关保护的 Fake Provider 业务切片：分析返回明确标为 `testing-fake` 且16项事实全部为 unknown 的结构，生图把原图转存为测试结果；该切片已经在真实环境完成分析、首次生成、再次生成、父子任务与结果转存验证，不验证模型效果。Fake 生成现采用两阶段执行：创建动作在事务中保存排队任务、幂等记录、额度和服务端执行输入并立即返回；第一次状态查询领取执行租约后才运行测试 Provider，后续并发查询只观察相同任务。这个受控试用实现让设备先保存 jobId，再验证退出恢复，但它仍是“查询触发执行”而非正式消息队列。继续修改、任务处理中退出后恢复、同键重放和物理手机相册保存均已完成交互验收。真实模式现复用与 Fastify 相同的 Qwen 分析和 Qwen Image Provider、证据门与确定性 Prompt Compiler。分析在 Provider 调用前持久化额度、源资产和幂等记录；生成任务以 `garment-generation-v2` 保存 Provider 模式、受控源图引用与 SHA-256、已编译 Prompt、基础请求指纹、父任务及累计修改，执行时再次校验源文件。小程序继续修改可以省略新的图片上传，由云函数在同一 OpenID 范围内读取父任务执行输入并复用最初商品图；每个子任务仍登记自己的源资产引用，清理器只有在不存在有效共享引用时才删除物理文件。父任务原图缺失时在额度准入前返回 `PARENT_ASSET_EXPIRED`。Provider 调用开始后的未知结果不会自动重试。该真实模式已完成核心链路付费真机验收；新增的父任务原图复用仍待重新部署后的真机验证。体验版直通只跳过 `trial_members` 指纹查询，不改变 OpenID 用户隔离、用户/全局额度、幂等、租约、云文件路径或过期清理。基础设施部署步骤与验证记录见 [微信云开发无模型费用验证](wechat-cloud-setup.md)。

跨运行时业务层已经新增 `packages/application`。当前切片定义了分析、生成任务、幂等、试用额度和资产仓储端口，并用可回滚的内存事务 Fake 验证“用户/全局额度原子预占 → 排队任务 → 幂等绑定”：并发重试只创建一个任务且只计一次额度，同键换请求会冲突，后续写入失败会回滚。Fastify 的首次生成和继续修改入口已经使用该准入用例，但仍搭配进程内仓储以保持单机 H5 行为。微信云函数代码已经实现 `garment_analyses`、`garment_assets`、`generation_jobs`、`idempotency_records`、`trial_usage` 的数据库适配器以及受控云文件上传、下载和删除适配器；五张集合已经在真实环境创建且只允许管理员访问。生成任务准入可以在同一事务中登记源资产，微信真实与 Fake 模式共用任务、幂等、额度和资产边界。微信生成任务另增加事务执行租约：模型调用前允许过期租约由同一请求接管，模型调用开始后发生中断则保守失败，避免自动重复付费调用。每日清理触发器先检查有效共享引用，再删云文件和过期资产元数据；失败记录保留重试，并清理已过期的分析、任务与幂等记录。租约、清理和真实模型核心链路均已完成对应真实验证；当前可以向少量微信平台体验成员开放，但仍不适合公开发布。

当前纵向切片中分析仍为同步请求，首次生成、再次生成和继续修改采用可轮询的异步任务：

```text
POST /api/v1/analyses multipart
  → 参数与文件校验
  → Alibaba Qwen VL Provider
  → garment-dna-v0.2 结构校验
  → 可见事实证据门控与三个设计方向
  → 用户选择一个方向
  → 保存分析结构和原图 SHA-256（一小时有效）

POST /api/v1/generations multipart + analysisId + directionId
  → 验证同一原图 SHA-256
  → 确定性 Prompt Compiler
  → 创建进程内任务并立即返回 202 + jobId
  → Alibaba Qwen Image Provider（开发默认）
  → 下载厂商临时结果
  → var/assets/{jobId}/result.{ext}
  → 保存 succeeded 或 failed

GET /api/v1/generations/{jobId}
  → 返回 queued / generating / succeeded / failed
  → H5 自动轮询，成功后展示稳定 GenerationApiResponse

POST /api/v1/generations/{jobId}/refinements multipart
  → 重新上传原始商品图并校验分支 SHA-256
  → 确认父结果仍存在并读取原始基础 Prompt
  → 本轮指令前置并确定性追加累计修改指令
  → 每轮都以原始商品图为生成底图，一次性重算选中方向和全部累计修改
  → 创建进程内任务并返回 202 + 新 jobId
  → 使用 garment-iteration-v1 调用当前生图 Provider
  → 保存新结果及 parentJobId，客户端通过相同状态接口查询
```

- 分析记录、生图任务和幂等记录保存在服务进程内；服务重启后无法恢复。
- 每日额度和并发队列同样只在服务进程内，服务重启后重置；同一幂等任务不会重复占用额度。
- 结果图保存在被 Git 忽略的本地目录。
- 原图只在当前请求内存中传递，不在本地持久化。
- 分析记录只保存原图不可逆 SHA-256，不保存原图 Base64 或文件。
- `Idempotency-Key` 分别防止分析和生图重复计费。
- 生成幂等记录同时保存请求指纹和任务 ID；从排队到失败始终绑定同一任务。同一键用于不同请求时返回冲突，客户端提交传输失败时可用原键重试。
- 同方向再生成和继续修改都重新上传原图；继续修改先校验原图 SHA-256，再保留父子记录和累计指令。父结果用于确认用户当前版本仍存在和建立历史关系，不再作为下一代像素输入。
- 结果父子关系与基础 Prompt 仅保存在服务进程内；客户端历史仅保存在当前页面状态中。
- 不提供 `analysisId` 与 `directionId` 时仍走 `garment-redesign-v1` 直接生成，用于降级和 A/B 对照。
- 当前实现只用于本地开发和真实效果验证，不用于公开部署。
- 配置共享访问码和额度后，可供本人或少量明确受邀者在单机环境试用；访问码不等于正式身份认证，结果资源也没有用户级授权。

完整接口见 [API 契约](api-contract.md)。

## 8. 任务状态

当前已实现生图任务的核心四态。H5/Fastify 分析仍为同步请求，任务状态只保存在当前进程；微信 Fake 与真实 Provider 模式会把分析、任务、幂等、额度和执行输入写入持久仓储，并由客户端保存未完成 jobId 后恢复查询。微信已有跨实例执行租约，但仍是“状态查询触发执行”，不是独立后台队列。上传前状态、取消、用户主动删除、正式 worker 队列与完整项目恢复仍属于目标能力。

```text
draft
  → uploading
  → ready
  → queued
  → generating
  → succeeded
  → failed
  → expired/deleted
```

- 同一幂等键不能重复创建付费生图请求：Fastify 在当前进程内实现，微信 Fake 与真实模式通过持久仓储实现；Fake 已完成真实云验证，真实模式已完成自动化契约验证。
- H5 只自动重试一次提交传输失败，并复用同一幂等键；Provider 错误不会自动重新生图。
- 任务查询的短暂网络失败可以自动恢复，不改变服务端任务。
- 厂商返回成功后必须立即转存临时结果 URL。
- 任务删除时同步安排原图和结果图删除，尚未实现。

## 9. 数据模型草案

当前已完成分析、资产、任务、幂等和试用额度的微信云数据库适配器及云文件存储适配器代码，Fake 与真实 Provider 业务动作均已接入；真实环境已创建集合并用 Fake 完成分析、首次/再次生成、继续修改、重进恢复、同键重放、手工清理和定时过期清理切片。排队任务会持久化受服务端严格校验的执行输入，状态查询再通过执行租约领取任务；执行租约已经实现、部署并完成真实实例超时验证，物理手机相册保存也已通过。真实 Provider 仍待云端密钥配置和付费真机验收；完整匿名会话和项目历史尚未完成。

- `sessions`：匿名或登录会话。
- `garment_projects`：一次服装改款项目。
- `garment_assets`：原始上传图和生成结果的受控云文件引用及过期时间。
- `design_directions`：设计方向和约束。
- `generation_jobs`：模型请求、状态、耗时和错误。

数据库只保存必要的文件引用，不保存完整图片 Base64。

## 10. 安全与成本控制

本节同时包含当前规则和上线目标：Key 仅服务端读取、单次一张、Provider 超时、可选共享访问码、进程内全局日额度、并发和生图启动间隔已实现；用户/IP独立限流、持久预算、告警与完整日志脱敏审计尚未实现。

- Key 只通过服务端环境变量或密钥管理服务加载。
- 所有生成接口设置用户级和 IP 级限流。
- 默认一次生成一张，显式确认后才增加数量。
- 为模型调用设置超时、并发上限和每日预算告警。
- 单机试用的额度是全局进程内计数，重启即重置，不替代正式预算系统。
- 日志对 Authorization、图片地址签名参数和用户输入中的敏感信息脱敏。
- 公开上线前更换开发期已经展示过的所有 Key。

## 11. 部署阶段

### 阶段一：本地开发

- 客户端和服务端本地运行。
- 使用本地或开发对象存储。
- Qwen Image 作为阶段性默认 Provider，万相保留为显式回退和 A/B 对照。

### 阶段二：受控单机 H5 测试（已实现，可选）

- 当前可在单机持久磁盘上向少量受邀者发布带共享访问码的临时链接。
- 扩大范围前接入正式对象存储、数据库、监控和持久限额。
- 不开放支付和公开注册。

### 阶段三：微信小程序体验版（开发中）

- 保留 H5 HTTP 路径，小程序通过统一业务网关切换到微信云存储和云函数。
- 使用本项目独立 AppID 与云开发环境，通过 OpenID 和体验成员范围保护付费调用。
- 将分析、任务、幂等、额度和结果引用迁移到持久云数据库与云存储。
- 先验证云函数实际执行边界，再决定是否需要独立任务执行服务。

完整清单见 [微信小程序体验版升级计划](wechat-mini-program-trial-plan.md)。

### 阶段四：公开 H5 与微信小程序

- 完成正式域名、备案、隐私文本和内容安全要求。
- 接入微信身份和平台分享能力。
- 根据真实评测确定主模型与回退策略。
