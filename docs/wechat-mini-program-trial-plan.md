# 微信小程序体验版升级计划

## 1. 目标与当前判断

下一阶段优先把现有服装改款链路部署为只对少量体验成员开放的微信小程序体验版，用真实手机验证产品价值。当前代码已经可以构建微信小程序，首个无模型费用的云开发探针已完成源码、自动化测试以及真实云环境上传、恢复和清理验收；正式构建仍默认通过 HTTP 调用单机 Fastify 服务。微信云端的分析、首次/再次生成、继续修改、任务查询、持久幂等和额度已经接入受控 Fake Provider；五张业务集合和 Fake 云函数已经部署，分析、首次生成、再次生成与清理已在真实环境通过，但继续修改、处理中退出后恢复和相册保存仍待真机验收，也没有调用真实模型。

这次升级不删除现有 H5，也不改变领域层、Prompt Compiler 或 Model Provider 的业务规则。H5 继续保留为本地开发和回归测试入口，小程序增加独立的云端传输与存储实现。

## 2. 已确认的部署边界

- 为服装改款项目注册独立的小程序 AppID，不复用 Body Health 的 AppID。
- 为新小程序创建独立的微信云开发环境，例如 `cloth-idea-test`，不读写 Body Health 的云函数、数据库或存储。
- 首轮只上传体验版并添加少量体验成员，不立即提交公开发布。
- 小程序通过云开发 SDK 调用本项目云函数；模型 API Key 只配置在云函数环境变量中，不进入客户端代码、构建产物或日志。
- AppID 和云环境 ID 是项目配置标识，不是模型密钥；AppSecret 和模型 API Key 不在聊天、文档或 Git 中传递。
- 当前 H5 的 Fastify HTTP 路径继续可用，作为本地调试与跨端回归基线。

## 3. 客户端升级

### 3.1 业务网关隔离

把当前页面对 HTTP 服务的直接依赖收敛为统一业务接口，例如：

```ts
interface GarmentGateway {
  getCapabilities(): Promise<TrialCapabilities>;
  analyzeGarment(input: AnalyzeGarmentInput): Promise<GarmentAnalysis>;
  createGeneration(input: CreateGenerationInput): Promise<GenerationJob>;
  getGenerationJob(jobId: string): Promise<GenerationJob>;
  createRefinement(input: CreateRefinementInput): Promise<GenerationJob>;
}
```

- `HttpGarmentGateway`：保留现有 H5 到 Fastify 的上传、请求和轮询行为。
- `WechatCloudGarmentGateway`：小程序使用云存储上传和 `wx.cloud.callFunction`，把云文件 ID 而不是图片 Base64 传给云函数。
- 页面和领域 Hook 只依赖 `GarmentGateway`，不得出现散落的 `process.env.TARO_ENV` 分支。

### 3.2 微信平台能力

- 在平台适配层初始化云开发，环境 ID 由构建配置注入。
- 上传前在手机端压缩和校验图片，保留原始文件哈希所需的信息。
- 支持 `cloud://` 结果下载和保存到相册，并处理用户拒绝相册权限的错误状态。
- 保存当前任务 ID 和最近一次项目引用；小程序退出或重新进入后可继续查询，不重新触发付费调用。
- 小程序用微信 OpenID 和项目维护的受邀用户白名单保护付费调用，同时只向平台体验成员分发体验版；H5 的受控访问码路径保留。
- 不在本地持久化完整图片 Base64、模型响应或长期有效的私有下载地址。

## 4. 云端升级

### 4.1 云函数职责

首轮按业务动作提供云函数入口，具体是否合并为同一函数由实现时的包体和部署验证决定：

- `analyze-garment`：下载临时原图、调用 Qwen 结构化分析、执行证据门并保存分析记录。
- `create-generation`：校验用户、分析、方向、额度和幂等键，先保存任务，再触发生图。
- `get-generation-job`：返回当前用户可访问的任务状态和结果引用。
- `create-refinement`：校验原图哈希与父任务，从最初商品图和累计指令重建结果。
- `cleanup-assets`：清理过期临时原图、生成结果和对应记录。

`packages/domain` 与 `packages/model-providers` 应被云函数复用；云函数不得复制一套提示词规则或直接把厂商协议写入业务入口。

### 4.2 数据与存储

第一版计划使用以下云数据库集合：

- `garment_analyses`：结构化分析、原图哈希、所属 OpenID、有效期。
- `garment_assets`：原图与结果图的受控云文件引用、类型、大小和有效期。
- `generation_jobs`：任务状态、方向、父子关系、累计修改、Provider、模型、错误和结果引用。
- `idempotency_records`：OpenID、业务动作、幂等键、请求指纹和绑定任务。
- `trial_usage`：用户和全局维度的分析/生图计数、日期、并发租约与启动间隔。

计划使用以下云存储路径：

```text
garment-source-temp/{openid-hash}/{jobId}.{ext}
garment-results/{openid-hash}/{jobId}/result.{ext}
```

- 原图只作为短期受控输入，模型调用结束后尽快删除；异常遗留由定时清理兜底。
- 厂商临时结果 URL 必须在任务成功前转存到本项目云存储。
- 数据库只保存文件引用和必要元数据，不保存完整图片 Base64。
- 正式保留期限在部署前确认并配置；不得默认永久保存体验用户图片。

### 4.3 幂等、异步与费用控制

- 调用模型前先原子写入幂等记录、任务状态和额度占用，重复点击或网络重试必须返回同一任务。
- 使用云数据库事务或条件更新实现额度预占和并发租约，不能沿用只在单个 Node.js 进程有效的 `Map` 和内存锁。
- Provider 已开始调用后不自动重试；只有明确未触发付费调用的传输错误才允许安全重试。
- 继续保持默认一次生成一张、全局并发 1、可配置生图启动间隔和每日预算上限。
- 云函数真实超时、后台执行持续性和外部请求限制必须先用假 Provider 和一次受预算保护的真实调用验证。若最长分析或生图无法在云函数边界内稳定完成，再通过新 ADR 选择任务执行服务，不在本计划中预先写死 CloudRun 或其他付费运行时。

## 5. 分阶段实施

### 阶段 A：不依赖真实 AppID

1. 已完成：新增 `GarmentGateway`，把现有 HTTP 实现收敛为可替换网关，保持 H5 行为不变。
2. 已完成代码与自动化验证：`WechatCloudGarmentGateway` 支持云存储上传、结构化分析、首次/再次生成、继续修改、任务轮询和重进恢复；Fake Provider 未启用时返回明确的“尚未部署”错误。
3. 已完成代码与自动化验证：新增 `@cloth-idea/application`，抽出持久幂等、用户/全局额度预占和排队任务创建用例；Fastify 首次生成与继续修改已切换，微信 Fake 业务动作也复用同一准入用例。
4. 已完成真实环境切片：分析、任务、幂等、额度和资产仓储接口及内存 Fake 已完成；微信云数据库五类仓储与云文件上传、下载、删除适配器已接 Fake 业务动作。五张真实集合已经创建并设为 `ADMINONLY`，分析、首次/再次生成和精确清理已经通过；其余真机交互仍待验收。
5. 保持 `npm run build`、`npm run build:weapp` 和现有自动化测试通过。

### 阶段 B：需要 AppID 和云环境 ID

1. 已完成：配置新小程序 AppID，并在微信开发者工具中导入项目。
2. 已完成：独立免费云开发环境已经创建并接入构建配置；无模型费用探针已按 [微信云开发无模型费用验证](wechat-cloud-setup.md) 完成部署。
3. 已完成：OpenID 权限、真实上传、持久恢复和主动清理均已通过，测试云文件和探针记录已确认消失。
4. 部分完成：五张业务集合已经创建并设为 `ADMINONLY`，Fake Provider 已部署；分析、选方向、首次生成、再次生成和清理已经通过。继续修改、任务处理中退出后恢复、保存结果和同键幂等重放仍待真机验收。模型 Key 此阶段仍无需配置。
5. 已完成代码、自动化与部署：增加任务执行租约和每日定时清理；触发器已真实删除专用过期文件和元数据。下一步先用 Fake 数据完成真实中断租约验收，再在明确预算内各执行一次真实分析、首次生成和继续修改。

### 阶段 C：体验版试用

1. 添加少量体验成员并上传体验版。
2. 收集方向质量、改款落实度、等待时间、失败率、下载和继续修改反馈。
3. 根据数据决定先优化模型、交互还是扩容基础设施，不在体验数据不足时提前建设完整正式账号和支付系统。

## 6. 体验版验收标准

- 真机完成“上传原图 → Qwen 分析 → 证据门 → 选择方向 → 生图 → 原图重建式继续修改 → 保存结果”。
- 退出小程序后重新进入，仍能恢复并查询已创建任务，不会重新调用模型。
- 同一按钮连续点击或同一请求重试只产生一个付费模型调用。
- 非体验成员或不在白名单中的 OpenID 不能调用付费模型。
- 分析、任务、额度和幂等记录在云函数实例重启后仍存在。
- 厂商临时图片已转存至本项目云存储，过期临时原图能够清理。
- H5 和微信小程序生产构建同时通过，H5 现有流程没有回归。
- 小程序构建产物、日志和数据库中不存在模型 API Key、完整图片 Base64 或 Authorization 请求头。

## 7. 暂不包含

- 正式公开发布、搜索开放和大范围推广。
- 微信支付、会员体系和按次计费。
- 纸样、尺寸表、完整工艺单和 3D 服装。
- 完整运营后台、多角色组织权限和长期归档。
- 在真实评测前再次更换默认分析或生图模型。

## 8. 项目负责人需要提供的信息

开发阶段 A 不需要真实账号信息。进入阶段 B 时只需要：

- 新小程序 AppID。
- 新云开发环境 ID。

AppSecret 和模型 API Key 不需要提供给代码贡献者；由项目负责人直接配置到微信云开发环境。
