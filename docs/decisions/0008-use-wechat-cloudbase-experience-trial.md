# 0008：使用独立云开发环境交付小程序体验版

- 状态：Accepted
- 日期：2026-08-27

## 背景

核心改款链路和单进程受控保护已经完成。原计划下一步在一台持续运行的 Mac 或服务器上暴露临时 H5，但这要求额外维护 HTTPS 入口、运行进程和网络可达性，并且进程内任务、额度和结果历史无法在重启后恢复。

项目负责人已经有微信小程序测试经验，希望下一轮直接用微信体验版邀请少量用户。现有 Taro 客户端可以构建微信小程序，Body Health 项目也证明了“客户端上传云存储、云函数调用模型、临时文件清理”的本地可行经验，但两个项目的数据和权限不应混用。

## 决定

1. 下一轮受邀用户试用以微信小程序体验版为主，为本项目注册独立 AppID 并创建独立微信云开发环境。
2. 保留现有 H5 和 Fastify HTTP 路径，用于本地开发、回归测试和可选的后续 H5 部署；本决定不删除或废弃 ADR-0003 和 ADR-0007 已实现的能力。
3. 客户端新增统一 `GarmentGateway`，H5 使用 HTTP 实现，小程序使用云存储与云函数实现，页面和领域逻辑不感知传输差异。
4. 小程序云端使用持久数据库保存分析、任务、幂等和试用额度，使用云存储保存受控输入与转存结果；不得把当前进程内仓储直接描述为小程序可用的正式实现。
5. 模型仍只由受控服务端代码调用。AppSecret 和模型 API Key 只配置在云端环境，不进入客户端或 Git。
6. 小程序使用 OpenID 和体验成员范围保护付费调用；H5 继续使用现有受控访问码。
7. 先验证云函数的真实超时、外部请求和后台执行边界。若不能稳定覆盖当前约40秒的分析和约20秒的生图，再单独决策任务执行运行时。

## 原因

- 体验成员扫码即可使用，适合小范围真机验证，不需要先公开发布。
- 独立 AppID 和云环境可以隔离 Body Health 的数据、权限、额度和故障。
- 云数据库与云存储能补齐跨函数实例和跨重启的任务、幂等、额度与结果恢复。
- 传输网关隔离可以保留现有 H5 投资，并避免在共享页面中散落微信专属分支。
- 先实测云函数边界，可以避免在没有证据时引入需要付费维护的新运行服务。

## 影响

- 当前单机受控 H5 仍可运行，但不再是下一轮小范围用户试用的首选部署方式。
- 小程序能成功构建不等于本决定已经实现；完成情况必须以 `docs/current-status.md` 和真机验收为准。
- 需要新增云端仓储、OpenID 授权、持久幂等、持久额度、存储清理和任务恢复，工作量高于简单填写 AppID。
- 新 AppID 和云环境 ID 不阻塞客户端网关与云端接口的本地开发，但阻塞云函数部署、真机云调用和体验版上传。
- 云开发资源和模型调用都必须设置预算与用量边界；体验版不等于免费或可公开扩容。

详细实施与验收清单见 [微信小程序体验版升级计划](../wechat-mini-program-trial-plan.md)。
