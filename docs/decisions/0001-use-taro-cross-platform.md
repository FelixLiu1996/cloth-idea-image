# ADR-0001：采用 Taro 跨端客户端

- 状态：Accepted
- 日期：2026-08-26

## 背景

产品计划先发布手机端 H5，并在验证后转为微信小程序。如果先开发依赖浏览器 DOM 的普通 H5，后续小程序迁移可能产生较大重写成本。

## 决定

客户端采用 Taro、React 和 TypeScript。业务组件和领域逻辑保持共享，图片选择、登录、保存、分享和导航等平台能力通过适配层隔离。

## 原因

- 同一代码库可面向 H5 和微信小程序。
- React 与 TypeScript 便于建立严格类型和组件边界。
- 可以先验证 H5 产品，再逐步补齐微信能力。

## 影响

- 禁止在共享代码中直接依赖 DOM 和浏览器专属库。
- 选用 UI、上传和图片处理依赖时必须检查小程序兼容性。
- H5 完成功能后仍需进行微信端编译和基础冒烟检查。
