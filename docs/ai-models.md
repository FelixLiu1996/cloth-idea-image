# 模型接入与选型

## 1. 目标

模型层需要支持参考图服装改款，而不只是文生图。重点考察：

- 原款主体与商品图构图的保留。
- 指定元素的精确保留。
- 廓形、结构、工艺和辅料的整体改款能力。
- 设计差异度与实际可生产性。
- 速度、稳定性、单张成本和商用条件。

## 2. 当前 Provider

### 2.1 阿里云百炼 Qwen VL

- 当前模型：`qwen3.7-plus`
- 当前状态：OpenAI 兼容视觉调用、原生严格 JSON Schema、结构校验、安全归一化、一次定向修复和错误标准化已实现。
- 当前角色：在付费生图前输出 `garment-dna-v0.2`、三个设计方向和生产风险。
- 证据规则：只有 `visible` 且置信度不低于 `0.75` 的视觉事实可以进入最终提示词。
- 真实验证：旧 `qwen3-vl-plus` 在7次调用中有4次结构校验失败；升级后，同一3张固定样本均由 `qwen3.7-plus` 在首次请求返回合法结构，耗时约40.6至44.7秒，修复请求均未触发。
- 兼容策略：支持严格 Schema 的模型使用 `json_schema` 并关闭思考模式；旧视觉模型仍可使用 `json_object`。对无歧义的数组、枚举和内部 ID 偏差先确定性归一化，仍不合规时只进行一次不重传图片的文本修复，两次调用共享150秒总预算。

### 2.2 阿里云百炼 Qwen Image

- 当前测试模型：`qwen-image-2.0-pro-2026-06-22`
- 当前状态：独立 Provider、Base64 参考图编辑、负面提示、同步生成、临时结果下载和本地转存已实现；默认 Provider 仍为万相。
- 调用策略：`prompt_extend=false`，避免厂商自动改写确定性 Prompt Compiler 的约束；`watermark=false`，输出1张；不指定 `size`，由模型保持输入长宽比并输出约1MP结果。
- 水印策略：正向提示明确删除输入中的型号、货号、价格、联系方式和水印，同时使用独立 `negative_prompt` 禁止任何可读文字。
- 真实验证：3张固定样本全部生成成功，耗时约16.3至18.0秒；两张带商家型号的输入均未在结果中复现文字。默认输出分别为896×1184、768×1344、896×1184，明显低于本轮万相输出分辨率。
- 效果观察：正面视角和关键保留项稳定；样本1改款深度优于同轮万相，样本2仍接近原款，样本3主要改变领型和袖口。当前样本数不足以替换默认 Provider。

## 3. Provider 规则

- 厂商 Key、Host 和模型 ID 只能存在于服务端配置。
- 每个 Provider 将厂商请求和响应转换为统一领域类型。
- Provider 必须返回厂商请求 ID，便于排查和对账。
- 结果图在成功后立即转存，不向客户端暴露厂商临时 URL。
- 测试阶段默认 `n=1`，只有用户明确选择后才增加输出数量。
- Provider 失败不得自动切换模型并重复计费，除非任务策略明确允许且用户已知情。服装分析只允许在结构校验失败时执行一次同模型文本修复，并汇总两次 token 用量。
- 分析 Provider 和生图 Provider 使用不同接口；生图 Provider 只接收领域层已编译的最终提示词。

## 4. 基准测试

当前基准任务：

> 将深靛蓝牛仔短外套改造成复古铁路工装款，进行整体结构改款，并完整保留黑白格纹翻折袖口。

固定提示词位于 `prompts/retro-workwear.txt`。横向比较必须使用同一输入图、同一提示词版本、同一输出数量和相近分辨率；每个模型至少测试3次后再下稳定结论。

## 5. 评分标准

| 指标           | 权重 | 说明                           |
| -------------- | ---: | ------------------------------ |
| 指定元素保留   |   25 | 格纹袖口等硬约束是否准确保留   |
| 原图与主体保留 |   20 | 构图、材质、品类和主体是否稳定 |
| 改款深度       |   20 | 是否覆盖廓形、结构、工艺和辅料 |
| 可生产性       |   15 | 结构和缝制逻辑是否合理         |
| 视觉质量       |   10 | 清晰度、真实感和细节完整性     |
| 速度与成本     |   10 | 单张耗时、成功率和费用         |

总分仅用于模型选择，不替代设计人员的专业判断。

## 6. 提示词版本

- 提示词必须有版本号，例如 `garment-redesign-v1`。
- 记录系统模板、设计方向、用户追加指令和最终组合结果。
- 修改硬约束表达、结构顺序或负面约束时提升版本。
- 不因单张偶然结果直接覆盖基准提示词。
- `garment-analysis-v1` 表示经过 `garment-dna-v0.2`、证据门和选中设计方向编译的生图提示词。

## 7. 上线前检查

- 核对商用许可、价格、限流、地域和数据处理条款。
- 确认内容安全、AI 标识和平台审核要求。
- 建立每日预算、用户额度、超时和并发控制。
- 更换所有开发期曾展示或共享过的 Key。
- 准备 Provider 停服、涨价或模型下线时的迁移方案。
